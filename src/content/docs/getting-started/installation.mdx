---
title: Running Fileglancer Locally
description: Install the fileglancer command-line tool to browse files on your own machine, and keep it up to date.
---

You don't need to install anything to use Fileglancer at Janelia: open [fileglancer.int.janelia.org](https://fileglancer.int.janelia.org) in your browser. Install the command-line tool only if you want to run your own Fileglancer server, for example to browse files on your laptop, or to use the [Python API](/features/python-api/).

## Install

Install Fileglancer as a standalone command-line tool. This creates an isolated environment for it and puts the `fileglancer` command on your PATH, the same way JupyterLab is installed.

With [uv](https://docs.astral.sh/uv/getting-started/installation/) (0.3 or newer):

```bash
uv tool install fileglancer
```

Or with [pipx](https://pipx.pypa.io/):

```bash
pipx install fileglancer
```

If you already manage Python environments yourself, you can instead `pip install fileglancer` into a virtual environment, or `pixi add fileglancer` to a Pixi project, and run `fileglancer` from inside that environment.

## Start the server

```bash
fileglancer start
```

This starts a server on `http://127.0.0.1:8000`, opens your browser, and serves your home directory by default. Run `fileglancer start --help` to see options such as `--port` and the directories to serve.

Apps you run from this server inherit your shell environment, so tools on your `PATH` and variables from your login scripts are available to jobs without further setup.

## Logging in

A server you start this way is yours alone: everything it does, it does as the user who started it, and there is no username to enter. The browser tab that `fileglancer start` opens is logged in automatically.

Any other browser, or the same browser after its session expires, is asked for a password. If you have not set one, the server generates a new password at every start and prints it in the terminal:

```
No simple_auth_password configured. Log in with this password for the lifetime of this process:

        k3vN8q-Zt1XwYb0a
```

To use a fixed password instead, uncomment `simple_auth_password` in your [config file](#configuration) and restart the server.

Logins survive server restarts: the key that signs the session cookie is generated once and kept with the server's data, so a browser that was logged in stays logged in.

:::note
The password is what stands between anyone who can reach the server and your files, so it is always required, even on a server bound to `127.0.0.1`. Serving other people from one Fileglancer server requires Okta login, which is how [fileglancer.int.janelia.org](https://fileglancer.int.janelia.org) runs; a password-only server cannot tell users apart.
:::

## Configuration

The first time you run `fileglancer start`, it writes a config file to `~/.config/fileglancer/config.yaml` and prints the path. Every start logs the file it read:

```
Reading config from /home/you/.config/fileglancer/config.yaml
```

The file lists every setting a personal server might need, all commented out with a short explanation, so you only uncomment what you want to change. Common ones:

```yaml title="~/.config/fileglancer/config.yaml"
# Password for the login page
simple_auth_password: your-password

# Directories to browse
file_share_mounts:
  - ~/
  - /data/shared

# Send apps to the cluster instead of running them on this machine
cluster:
  executor: lsf
  queue: normal
```

Edit the file and restart the server to apply changes. To read a different file, pass `--config PATH` or set `FGC_CONFIG_FILE`. Any setting can also be given as an environment variable prefixed with `FGC_`, which takes precedence over the file; a `.env` file next to the config is read for these too.

The server's database and session key live in `~/.local/share/fileglancer/`.

## Upgrade

```bash
uv tool upgrade fileglancer   # or: pipx upgrade fileglancer
```

:::caution[Avoid `uvx fileglancer`]
`uvx` runs a tool from a disposable cached environment. If that environment was interrupted while being built, or is shared between machines or uv versions, later runs fail with `Package fileglancer does not provide any executables`. Running `uv cache clean fileglancer` clears the bad cache, but a persistent `uv tool install` avoids the problem entirely.
:::

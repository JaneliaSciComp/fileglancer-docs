The fastest way to try Fileglancer is to run a personal server on your own computer. It takes one command, there is nothing to install, and nothing is left behind except a small cache. Fileglancer opens in your browser with your home directory ready to browse.

This page covers that path first, then two other ways to run Fileglancer: from a checkout of the source code, and as a shared server for your lab or institution.

## Run Fileglancer with uv

[uv](https://docs.astral.sh/uv/) is a fast Python package manager. Its `uvx` command downloads a Python tool into a cache and runs it, so you don't need to set up Python or a virtual environment yourself. Fileglancer runs on macOS and Linux.

<Steps>
1. **Install uv**

   <Tabs>
     <TabItem label="macOS / Linux">
       ```bash
       curl -LsSf https://astral.sh/uv/install.sh | sh
       ```
     </TabItem>
     <TabItem label="Homebrew">
       ```bash
       brew install uv
       ```
     </TabItem>
     <TabItem label="pip">
       ```bash
       pip install uv
       ```
     </TabItem>
   </Tabs>

   Other installation options are listed in the [uv documentation](https://docs.astral.sh/uv/getting-started/installation/). Open a new terminal after installing so that `uvx` is on your `PATH`.

2. **Start Fileglancer**

   ```bash
   uvx fileglancer start
   ```

   The first run takes a minute or two while uv fetches Python (if needed) and the Fileglancer package. After that, starting is nearly instant. When the server is ready, your browser opens to Fileglancer and you are logged in automatically as your system user.

3. **Browse your data**

   Your home directory is available under the **home** file share path in the left sidebar. Navigate into folders, inspect files, and open any Zarr or OME-Zarr dataset to see its metadata and a thumbnail. The [Core Workflows](../../workflows/navigation/) guides cover the interface in detail.

4. **Stop the server**

   Press <kbd>Ctrl</kbd>+<kbd>C</kbd> in the terminal and confirm when prompted.
</Steps>

### Browse more than your home directory

Pass one or more file share paths with `-f` to make other directories browsable. The special prefix `~/` expands to your home directory.

```bash
uvx fileglancer start -f ~/ -f /data/microscopy -f /mnt/shared
```

Useful options:

| Option | Effect |
|--------|--------|
| `-f PATH`, `--file-share-mounts PATH` | Add a browsable file share path. Repeat for each path. |
| `--port N` | Listen on a specific port (default 8000). If the port is busy, the next free port is used. |
| `--no-browser` | Start the server without opening a browser. |
| `--help` | Show every option. |

<Aside type="tip" title="Picking up new releases">
uv caches the version it downloaded. To make sure you run the newest release, use `uvx fileglancer@latest start`.
</Aside>

### What a personal server can and can't do

A personal server is great for exploring your own data, checking OME-Zarr metadata, and opening images in a viewer. It has limits that come from running on your machine:

- **Links only work while the server is running.** Data links and View links point at your computer, so they stop working when you stop the server.
- **Only you can use it.** The server listens on `127.0.0.1` and logs in your system user, so it is not reachable by others.
- **Viewers are external.** Images open in public viewer instances such as the Neuroglancer demo site. Editing a View in the embedded viewer requires a shared deployment that serves its own Neuroglancer.

To share data reliably with colleagues, you need a shared deployment. See [Deploy a shared server](#deploy-a-shared-server) below.

## Run from source with Pixi

If you want to modify Fileglancer or contribute to it, run it from a clone of the repository. Fileglancer uses [Pixi](https://pixi.sh) to manage its Python and Node.js environments, so Pixi is the only tool you need to install first.

<Steps>
1. **Clone the repository**

   ```bash
   git clone https://github.com/JaneliaSciComp/fileglancer.git
   cd fileglancer
   ```

2. **Install the package in development mode**

   This installs the backend dependencies and builds the React frontend.

   ```bash
   pixi run dev-install
   ```

3. **Create a configuration file**

   ```bash
   cp docs/config.yaml.template config.yaml
   ```

   Edit `config.yaml` to set `file_share_mounts` and any other settings you want to change.

4. **Launch the server**

   ```bash
   pixi run dev-launch
   ```

   Open [localhost:7878](http://localhost:7878) in your browser. The backend reloads automatically when you change Python files. To rebuild the frontend on change as well, run `pixi run dev-watch` in a second terminal.
</Steps>

The [development guide](https://github.com/JaneliaSciComp/fileglancer/blob/main/docs/Development.md) in the repository covers configuration options, running the tests, HTTPS, viewer configuration, and the cluster settings used by the Apps feature.

## Deploy a shared server

Fileglancer is designed for a persistent, shared deployment on your institution's network. In this mode a single server runs on a machine that can see your network file systems, users log in through your identity provider, and the Data Links and Views they create keep working as long as the server is up.

A shared deployment adds a few pieces around the Fileglancer server:

- **Per-user file access.** The server runs as root and accesses files as the logged-in user, so everyone sees exactly the files they have permission to read on the file system.
- **Single sign-on.** Users authenticate with your institution's OAuth/OIDC provider (Janelia uses Okta).
- **A reverse proxy.** Nginx terminates TLS, serves the static frontend, and can serve a Neuroglancer instance from the same origin so that Views can be edited in place.
- **A database.** SQLite works for small deployments; PostgreSQL is recommended for larger ones.
- **Optional integrations.** A compute cluster for the [Apps](../../workflows/apps-and-jobs/) feature, and the [x2s3](https://github.com/JaneliaSciComp/x2s3) proxy for sharing data on the public internet.

The key settings are the file share paths to expose, the database URL, the public URL of the server, and the OAuth client details. Follow the installation steps in the fileglancer-hub README, substituting your hostname, certificates, and identity provider.

Setting up a shared deployment is a job for a system administrator. If you'd like help adapting Fileglancer to your environment, [open an issue](https://github.com/JaneliaSciComp/fileglancer/issues) on GitHub. We're glad to collaborate.
</Aside>
